# 0013 · 执行层架构定稿（2026-11-27）

> 背景：11-19~11-27 这一周，系统从"每天跑但实际不太会交易"修到"确实会交易、且能被验证"。
> 这份记录把执行层的最终形态与判定规则钉住，避免以后再出现"两套实现各自漂移"。

## 结论（先看这个）

1. **只有一个算单器**：`quant/automation/rebalance.py::plan_rebalance`。美股、港股、A 股都走它，
   差异用参数表达（整手、T+1 可卖量、权重是否归一、最小下单金额、换手上限）。
2. **只有一套下单入口**：`quant/automation/execution.py::execute`，受哈希链台账约束，
   同一快照/交易日/轮次只能消费一次。
3. **先卖后买之间必须等**：提交卖单后轮询当日委托（默认 90s 上限），再提交买单。
4. **上实钱由闸门判定，不由人拍**：`scripts/promotion_check.py` 七项硬指标，`docs/runbook-go-live.md` 是操作顺序。

## 为什么这么定（一周内踩到的事故）

| 事故 | 根因 | 现在的约束 |
|---|---|---|
| 港股需要 93% 换手却只有 1 笔买入 | `cleanup_orphans` 默认关闭 + 只会加仓不会减仓 | 目标外清仓 + 超配减仓 + 单轮换手上限 50% |
| 港股残留漂移 74% 怎么调都回不来 | 预算按「账户权益 × 固定袖套比例」，与实际资金分布不符 | 预算 = 袖套市值 + 可动用现金份额 |
| 27 笔 `Insufficient Credit Limit` | 卖单未成交就按「卖出所得」下买单 | 先卖 → 等成交（≤90s）→ 再买 |
| 同一标的可能被卖两次 | 再平衡与风控模块各自有幂等台账、互不相识 | 风控读当日期望订单去重 |
| 第二轮补单从未生效 | `weight_drift` 返回值语义变更后触发条件恒假 | 补单触发用 `--strict`；契约测试钉住 |
| 重构后重复下单风险 | `pending`（在途委托）算出来却没用 | pending 同时从 holdings 与 targets 剔除 |
| 感恩节把美股流程卡死 | 门禁只跳周末 | `quant/data/market_calendar.py` 规则化日历 |
| A 股另有一套 138 行算单 | 历史上两套实现 | 并入通用算单器（净减 123 行） |

## 判定规则（写在代码里，不靠记忆）

- **一次消费**：`consumption_key(market, snapshot, session, pass_no)`；全部委托未落地时自动 `release`
- **两轮上限**：`pass_no ∈ {1,2}`，一天最多两轮，避免过度换手
- **单笔/单日/单票/整手/现金留底**：`Policy` + `rebalance.Limits`
- **涨跌停/T+1**：A 股用 `sellable`（可用余额）限制卖出量
- **风控与主单去重**：读 `state/expected/<日期>_<市场>.json`
- **下单前模拟**：`scripts/simulate_plan.py` 不通过就不下单
- **开跑前金丝雀**：`scripts/canary.py` 一条命令回答能不能跑

## 被否掉的方案（留档，避免反复讨论）

| 方案 | 否掉的原因 |
|---|---|
| 袖套改用四相位共识 | 同仓位复测无优势，换手还高 20%（第 26 轮更正） |
| A 股启用波动率目标 | 2023 起夏普 0.74→0.57、收益 11.5%→7.0%，回撤只改善 1.3pp |
| 港股启用波动率目标 | 25% 仓位下已实现波动本就低于目标，缩放系数恒为 1，无效果 |
| 美股调仓周期改 40 日 | 收益与换手更优但回撤更差，差异不足以下结论，维持 20 日并记为待跟踪 |
