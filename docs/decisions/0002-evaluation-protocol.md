# 决策 0002 · 评估协议与停机规则

- 日期：2026-10-22
- 状态：生效（所有后续迭代必须遵守）
- 前置：决策 0001

## 为什么需要单独定义

「不断优化」是最容易自欺的过程：每改一次代码，总能在历史上找到更好的一组参数。
如果没有事先写死的评估协议，优化就退化成对历史的拟合。所以本文件的规则
**先于任何回测结果**确定，且改动需要单独写决策文档。

## 数据切分（不可越界）

| 区间 | 起止 | 用途 | 允许调参 |
|---|---|---|---|
| 训练/开发 | 2018-01-01 ~ 2022-12-31 | 因子构建、参数选择 | ✅ |
| 验证 | 2023-01-01 ~ 2024-12-31 | 选择模型/确认稳健性 | ⚠️ 只能看一次结论 |
| 样本外（OOS） | 2025-01-01 ~ 至今 | 最终检验 | ❌ 禁止 |

**纪律**：开发期只跑训练区间。OOS 只在「模型冻结」后跑一次，且结果必须
原样记录进 `docs/journal/`，不许「跑完不好看再调」。

## 主指标（按重要性排序）

1. **年化超额收益**（相对沪深300，同成本同宇宙）
2. **信息比率 IR**（超额/跟踪误差）
3. **最大回撤**（决定这套策略能不能拿住）
4. **年化换手率**（决定成本侵蚀，>15 倍/年基本不可行）
5. 夏普比率（辅助，受波动率影响大，不作唯一依据）

绝对收益不是主指标：2018-2026 包含两轮牛熊，绝对收益主要由 beta 决定。

## 稳健性检查（每轮必做）

- **成本敏感性**：滑点 0 / 5 / 10 / 20 bp 四档，报告收益衰减曲线；
- **调仓频率敏感性**：5 / 10 / 20 日；
- **持仓数敏感性**：20 / 30 / 50 只；
- **子区间稳定性**：按年拆解，不允许「只靠某一年赚钱」；
- **方向一致性**：同一因子在中证500（不同股票池）上的 IC 方向是否一致。

## 停机规则（预设，不许临场改）

| 条件 | 动作 |
|---|---|
| OOS（或验证集）连续 2 轮无改善 | 停止该优化方向，写复盘 |
| 同一参数被调超过 3 次仍无提升 | 冻结该参数 |
| 单轮改进 < 1% 年化（低于成本敏感性区间） | 判定为噪音，不采纳 |
| 改进只在单一子区间出现 | 判定为过拟合，不采纳 |
| 换手率年化 > 2000% | 直接否决，不管收益多高 |

## 每轮迭代的固定产出

1. 代码变更（git commit，message 写清假设）；
2. `docs/journal/NNNN-<主题>.md`：假设 → 实现 → 数字 → 是否采纳 → 下一步；
3. 更新 `reports/` 下的指标 JSON；
4. 若改变了评估口径，必须新增决策文档而不是改本文件。

## 10 条针对「协议本身」的攻击性自问

**Q1. 你说 OOS 只跑一次，怎么证明你没偷看？**
A：OOS 跑之前先在 journal 里登记「本轮假设与预期」，跑完原样贴结果。做不到绝对证明，
但留下时间戳与预期，事后可检验。

**Q2. 训练集 5 年够吗？A 股 2018-2022 包含一次熊市、一次结构牛，样本是否太单一？**
A：不够，这是已知缺陷。补偿手段：按年拆解稳定性、跨指数（300/500）验证。
若跨池方向不一致，直接判为不稳健。

**Q3. 用年化超额做主指标，如果策略只是高 beta 呢？**
A：所以同时看 alpha 与 beta，beta > 1.1 的策略视为「杠杆式 beta」，不算 alpha。

**Q4. 换手率上限 2000% 是不是拍脑袋？**
A：是经验值：双边成本约 0.1%（佣金+印花税+滑点），2000% 换手 ≈ 2% 年化成本，
已接近优秀策略超额的一半，再高基本不可行。会做成本敏感性来验证这个阈值。

**Q5. 成本敏感性四档是不是太粗？**
A：是刻意的：我们要的是「策略能承受多少成本」的拐点，不是精确曲线拟合。

**Q6. 子区间稳定性用「按年」够吗？会不会某年只有 3 个月的行情？**
A：不够细。所以加一条：按月拆解，若超额收益集中在连续 3 个月内，标记为「事件驱动型」，单独评估。

**Q7. 如果所有因子在中证500 上方向都不一致，是因子问题还是池子问题？**
A：先归因：小市值股票流动性差、涨跌停多，因子方向天然容易翻转。若 300 上稳定、500 上翻转，
判为「池子依赖」，只在 300 上使用并在报告里写明适用范围。

**Q8. 你说「单轮改进 < 1% 年化不采纳」，但如果多个 0.5% 的改进叠加呢？**
A：允许叠加，但必须**一次性合并验证**叠加后的总效果，不允许逐个申报。
否则就是变相的参数扫描。

**Q9. 我怎么知道回测引擎本身没有 bug（例如净值算错）？**
A：三重校验：① 单元测试（21 个）；② 用「全现金不交易」跑一遍，净值应恒等于 1；
③ 用「买入持有基准」跑一遍，结果应与基准收益一致（扣除费用）。第二、三条会写进测试。

**Q10. 如果最后 OOS 表现很差，这个项目算失败吗？**
A：不算。项目的交付物是「可复现的研究流程 + 诚实的结论」，
包括负面结论。把 OOS 失败原因归因清楚，比刷一个好看的数字更有价值。

## 判断

**结论：GO。** 本协议替代「看哪个回测数字好看」的决策方式，后续所有 journal 必须引用本文件条款。
